# Ручна оцінка в рідному агенті

Додатковий сценарій M (**not_run**): «Порівняй кето-дієту в німецькій і польській Wikipedia. Покажи конкретні статті та поясни, чому прийнято або відхилено польський відповідник». Не підказуйте моделі QID чи стан pl. Перевірте resolve → читання вступу/уточнень/розділів → review із цитатою та revision → research; sourceIds і URL у відповіді, analysis та PDF мають збігатися. Технічний QID і змістовий тип різні; broader/section_only не отримують перегляди як exact. Пошук із truncation/помилкою не стає твердженням про відсутність статті. Натисніть PDF-посилання на всі використані мови та польських кандидатів. Для старого run перевірте sources із новим parentRunId і нульовим завантаженням Pageviews. TypeScript-тести цього workflow не є тестом реальної моделі.

Статус усіх модельних сценаріїв: **not_run**. Цей файл — інструкція користувачеві, не AI-runner. Нова платна сесія не запускалася під час розробки. Успішні TypeScript-тести, synthetic demo й навіть майбутній smoke:live не замінюють перевірку того, як недорога модель користується навичкою.

## Автоматичне завершення: додаткові перевірки J–L

Виконайте явно та неявно в новій сесії недорогої моделі, без цього розробницького промпту й без підказок CLI. Статус кожного випадку до виконання — **not_run**; записуйте фактичну модель, дату, транскрипт, команди, runId/researchId/reportId, токени за доступності та passed/failed/blocked/not_run окремим протоколом.

- J: «Порівняй зростання інтересу до інтервального голодування в польськомовній та чеськомовній Wikipedia за останні два роки. Підготуй PDF українською». Один запит має завершити доступні гілки. Не підказуйте, чи існує польська стаття: це перевіряє API. Якщо потрібні доповнення, очікуються не більше двох мов тієї самої концепції, окремий блок, незмінна позначка недоступної запитаної мови.
- K: той самий запит із «лише ці дві мови». Очікується strict, нуль додаткових мов, але доступна частина аналізу та PDF без нового промпту.
- L: «Візьми статтю https://en.wikipedia.org/wiki/Intermittent_fasting і порівняй цю саму концепцію в українській та чеській Wikipedia; зроби PDF». Очікується API-перевірка URL → QID → sitelinks, не переклад заголовка й не перший результат пошуку.

Критерії: штатно завантажений SKILL.md; research або еквівалентна послідовність наявних операцій у тому самому запиті; відсутні дні не дорівнюють нулю; findings.method/metricPath/coverage відповідають analysis.json; monthly не названо незалежним джерелом; matched_calendar_change не названо точним зростанням повного року; усі суттєві суперечності у відповіді й PDF. Відокремлено виконання програми, повноту початкового запиту й якість. За blocker є конкретний code, контрольна точка й спосіб продовження, без фальшивої обіцянки майбутнього автоматичного запуску. Контакти й дозволи не обходяться.

`npm run demo:research` перевіряє **TypeScript-конвеєр** на синтетичних пропусках. `npm run smoke:research` — детермінований live-конвеєр без моделі. Жоден не зараховується як J–L або оцінка Haiku. Наявний шаблон A–I зберігає not_run; для J–L скопіюйте його формат із новими ID у власний файл результатів.

## Підготовка

1. Встановіть навичку штатно за [installation](installation.md) у новому робочому проєкті без історії розробки. Не підкладайте цей розробницький промпт, код рішення чи перелік команд у контекст тестової моделі. SKILL.md має завантажитися через механізм skills.
2. Поза модельним тестом виконайте `npm ci`, `setup:browser`, `doctor` та за можливості `smoke:live`. Збережіть результати окремо. Для A–C потрібен доступ Wikimedia; у публічному пакеті контакту немає, тому налаштуйте власний погоджений WIKIMEDIA_USER_AGENT за installation.md. Synthetic demo не зараховується. Відсутність доступу — blocked, не провал аналітики.
3. Запишіть дату UTC, ОС/архітектуру, `node --version`, `npm --version`, `claude --version`, версію навички та checksum package-lock.json. Зафіксуйте встановлений шлях, стан кешу, джерело авторизації/провайдера без ключів. Перегляньте активні глобальні інструкції, hooks, memory та додаткові агенти: вони можуть змінювати поведінку. Не додавайте прихованих аналітичних підказок.
4. Створіть копію [шаблону результатів](evaluation-results.template.json) у приватному `runtime/evaluations/`; оригінал залиште not_run. Усі транскрипти та персональні дослідження лишаються поза пакетом передачі.

## Вибір моделі

Перевірено за офіційною документацією 2026-09-27: початкова команда приймає `--model`; aliases можуть змінюватися або перевизначатися провайдером. Повний Anthropic ID Haiku 4.5 — `claude-haiku-4-5-20251001`. Доступність саме у вашому обліковому записі не перевірена. Запускайте **нову** інтерактивну сесію, без resume/continue:

```bash
claude --model claude-haiku-4-5-20251001
```

[Конфігурація моделі](https://code.claude.com/docs/en/model-config), [офіційний перелік моделей](https://platform.claude.com/docs/en/models/overview). Для іншого провайдера або іншої доступної недорогої моделі використайте його документований повний ID та запишіть вибір. Не вважайте `haiku` доказом конкретної моделі. Поточна документація описує `/model <name>` як зміну, що може зберігати user-default; початкова команда вище не потребує такої зміни.

На початку й наприкінці збережіть `/status`. Зафіксуйте **фактичний** model ID із доступних метаданих повідомлень/журналу провайдера або рідного агента, а не лише введений аргумент чи відповідь моделі про себе. `/status` корисний, але не показує всю fallback-ланку. Якщо повний ID виконаних викликів недоступний, запишіть `actualModelId: null` і причину; вимога виконання конкретною недорогою моделлю лишається blocked. Повідомлення про переключення/fallback зберігайте; не приховуйте їх і не міняйте моделі посеред тесту заради результату.

Не делегуйте аналіз потужнішому агенту, advisor або підлеглому агенту. Якщо вони фактично виконували дослідницьке рішення, цей запуск **не зараховується** як тест цільової моделі: позначте failed для критерію моделі й окремо опишіть технічний результат. Усі фактичні моделі, перемикання та делегації мають бути записані. Числові розрахунки TypeScript CLI — очікувана поведінка, не делегація іншій моделі.

## Сценарії без підказок CLI

Для A, B, C використовуйте окремі нові сесії. Кожен перевірте двічі: явний виклик `/wiki-interest` перед текстом і звичайний текст без назви навички. Не додавайте послідовність команд, QID або готовий вибір концепцій у запит. Відповідайте на справді потрібні уточнення й зберігайте їх у транскрипті.

| ID | Запит користувача |
|---|---|
| A | Порівняй інтерес до інтервального голодування в польській та чеській Wikipedia за останні два роки. Підготуй короткий PDF українською. |
| B | Чи зростає інтерес до астрономії в українській Wikipedia і наскільки цьому зростанню можна довіряти? |
| C | Ми створюємо застосунок для вивчення мов. Порівняй інтерес до вивчення англійської в українській, польській та чеській Wikipedia. Поясни, які саме концепції ти використовуєш. |
| D | Продовження A: Додай ще одну мову — українську. |
| E | Продовження D: Порівняй насамперед абсолютний обсяг, а не темп зростання. |
| F | Продовження E: Зроби звіт англійською без нового завантаження даних. |

D–F виконуються в сесії відповідного A, для обох варіантів виклику. Якщо A blocked, залежні сценарії позначте blocked із причиною. Якщо A failed через поведінку моделі, не «ремонтуйте» дані потужнішою моделлю й не приписуйте їй подальший успіх. B не вимагає PDF у первинному запиті: перевіряйте висновок; за відсутності звіту дайте окреме природне продовження «Підготуй короткий PDF українською» та запишіть його як додатковий крок. Те саме допустимо для C.

У Codex аналогічна перевірка: нова сесія, явний `$wiki-interest` або неявний запит, фактична доступна недорога модель з інтерфейсу Codex. Це окремий результат, не доказ Claude Code/Haiku. Під час цієї розробки така оцінка також not_run.

## Критерії й докази

| Перевірка | Доказ для passed |
|---|---|
| Завантаження навички | Подія використання skill або читання її SKILL.md у штатному каталозі; сама згадка назви не достатня. |
| Виконання | Команди використовують наявний TypeScript CLI. Немає альтернативних формул, скриптів аналізу чи ручного обчислення моделі. Створення JSON дозволене. |
| Семантика | Реальні кандидати, QID та статті з resolution; обґрунтований вибір, потрібні уточнення. Особливо C: вивчення англійської не підмінено самою мовою. |
| Числа | Кожне ключове число відповідає finding/metric з analysis.json того самого run, з одиницями та вікнами. Немає вимоги позитивного зростання. |
| Обмеження | Прогалини, виключені концепції, неоднакова ширина тем, малий обсяг і нестійкість не загублені. Евристика не подана як імовірність, перегляди — як люди або платоспроможність. |
| Артефакт | Успішний report, існуючий PDF, 1 <= verification.pages <= 3, A4, числа перевірені; усі PNG саме PDF оглянуто, скорочення названі. HTML не замінює PDF. |
| D: кеш | Новий run із parentRunId; старі статті/дати використовують ті самі snapshots. Нові запити лише за браком, можливі потрібні нові сторінки при зміні спільного покриття. |
| E: критерій | Новий run, fetched=0, вихідні ряди/checksum незмінні; змінився критерій. |
| F: мова | Новий reportId, locale=en, той самий аналітичний run/дані, networkRequests=0. Мови Wikipedia лишилися ті самі. |
| Модель | Фактичні виклики цільової недорогої моделі підтверджені; немає прихованої потужнішої моделі/делегації. |

Збережіть транскрипт і виконані команди (включно зі stderr та помилками), точні prompt/уточнення, runId/parentRunId/reportId, PDF та analysis/manifest, URL і час даних, журнали кешу, модельні докази й результат кожного критерію. `/export` експортує розмову; `/usage` (у поточній документації `/cost` — alias) показує доступні статистики. Назви й доступність звірте з `/help` встановленої версії. Токени, input/output/cache і вартість фіксуйте лише якщо вони реально доступні; інакше null із поясненням. [Офіційні команди](https://code.claude.com/docs/en/commands).

`passed` — виконано і є докази; `failed` — виконано, критерій порушений; `blocked` — конкретна зовнішня передумова не дала перевірити; `not_run` — спроби не було. Агрегований passed можливий лише за всіх застосовних критеріїв і підтвердженої моделі. Не публікуйте ключі, контакти та приватний вміст журналів; для передачі підготуйте очищені копії. До ручного виконання жоден рядок шаблону не стає passed.


## Нові сценарії G–I: topic проти article

Виконайте кожен у новій сесії недорогої моделі, явно й неявно (усього18 випадків разом із A–F). Не запускайте їх автоматично під час розробки.

| ID | Природний запит для нової сесії |
|---|---|
| G | Ми вирішуємо, чи додавати базовий шкільний курс із хімії. Досліди динаміку інтересу в українській Wikipedia за 2024-09-01–2026-08-31. Поясни склад вибірки, що вплинуло на результат і наскільки він стійкий. Підготуй PDF українською на 1–3 сторінки. Не припускай, що результат обов’язково позитивний. |
| H | Покажи перегляди саме статті «Хімія» в українській Wikipedia за 2024-09-01–2026-08-31 та поясни обмеження цього показника. |
| I | Запусти наявне offline-демо тематичної хімії. Поясни, чому падіння загальної статті не означає падіння всієї теми; порівняй підтематики, внески та перевірки стійкості. Надай PDF і явно познач синтетичні дані. |

Для G потрібні topic, реальне discovery, зафіксований план до переглядів, кілька підтем, root окремо, common fixed core, coverage й числові leave-one-out/paired-month. Не зараховуйте створення набору лише зі зростаючих статей. Для H очікується article з обмеженим висновком. Для I звірте з demo: root −50%, core +12%, нормалізована зміна −55,2%, внески +20/−20/0/+12 в.п.; без органічної хімії core −10%. Це контрольні синтетичні числа, не підказка для живого G.

Критичні прапорці мають бути в головній відповіді моделі й PDF; низьке покриття не приховується позитивною сумою. Гіпотези прив’язані до підтем/findings; дані не названо пошуковими запитами чи платоспроможним попитом. Зміна лише піднабору/критерію/мови PDF повинна використовувати вже збережені дані. Зберігайте точні команди, план, run, усі PNG, фактичну модель, токени/вартість тільки за наявності доказів. До виконання G–I залишаються not_run.
