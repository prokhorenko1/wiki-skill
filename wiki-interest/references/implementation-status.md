# Стан реалізації та перевірок

Навичка містить article/topic-аналіз, resolve/review для мовних відповідників, bounded discovery й фіксовані тематичні плани, research із мовною політикою, діагностику пропусків та стійкості, незмінні snapshots і відтворення PDF. Числа обчислює TypeScript CLI; вибір концепцій і змістові рішення виконує рідний агент. [Методологія](methodology.md) і [контракти](contracts.md) визначають точні межі.

## Перевірка чистого публічного набору — 2026-09-27

Перевірено на macOS ARM64 з Node.js 24.21.0 у новій тимчасовій директорії. Вона містила поточні вихідні файли без runtime, node_modules, приватної конфігурації та symlink на оригінал; залежності й Chromium встановлено заново.

| Перевірка | Фактичний результат |
|---|---|
| `npm ci --include=dev` | passed; залежності встановлено з незміненого lockfile |
| `npm run setup:browser` | passed; власний Chromium чистої копії |
| `npm run doctor -- --offline` | passed; offlineReady=true без WIKIMEDIA_USER_AGENT |
| `npm run check` | passed; TypeScript, 137/137 тестів у 15 файлах, валідатор SKILL.md, посилань і JSON-прикладів |
| `npm run demo:offline` | exit 0; fixtures, очікуваний partial, PDF на 2 A4, 18 числових перевірок, networkRequests=0 |
| Публічний склад | правила ігнорування та відносні посилання перевірено; код, lockfile, шаблони й fixtures доступні |

Початкову спробу встановлення обмежив DNS sandbox; повтор із дозволеним мережевим доступом завершився успішно. Для PDF-тестів дозволено локальний запуск Chromium. Live-дослідження та платні LLM-виклики не виконувалися. Візуальний огляд демонстраційного PDF у цьому етапі не проводився.

## Межі підтвердження

- Автоматичні тести та синтетичні демонстрації перевіряють програму, а не якість суджень моделі чи повноту live-даних.
- Повний live-smoke поточної версії не підтверджений. Попередні спроби блокувалися конфігурацією контакту або мережевим доступом; під час підготовки до публікації live-запити не виконуються.
- У публічному package.json немає контакту Wikimedia. Новий користувач надає його через агента перед першим live-запитом; offline працює без нього. [Налаштування](installation.md#конфігурація-wikimedia).
- Linux, Windows, а також незалежний наскрізний запуск у Codex/Claude Code на недорогій моделі ще не перевірені. [Сценарії оцінки](evaluation.md) залишаються `not_run`.
- Технічний збіг QID не доводить змістового exact. У старих знімках може бракувати тексту й revision: historical-відтворення не перетворює pending на перевірений висновок. Обмежений або перерваний пошук не доводить відсутності статті.
- PDF перевіряється програмно, але остаточний візуальний огляд усіх сторінок залишається окремим кроком. Успіх PDF не означає повноти дослідження.

## Відтворення перевірок

З чистої копії виконайте встановлення за [README](../README.md), потім `npm run check` і `npm run demo:offline`. Додаткові синтетичні сценарії — `npm run demo:topic` і `npm run demo:research`. Результати записуються в новий локальний runtime; чужі runId та приватні журнали не потрібні.

Аудит власного збереженого run: `npm run --silent audit:sources -- --run "$RUN_ID"`. Без `--live` він використовує історичні знімки. Додавання `--live` явно вмикає запити метаданих і потребує контакту; Pageviews заради такого оновлення не перезавантажуються. [Докази та джерела](sources.md).

Подальша перевірка має зосередитися на live-доступі, змістовій релевантності різних тематичних наборів, незалежній недорогій моделі й інших ОС. Новий AI-runner або сервер для використання навички не потрібний.
