# wiki-interest

Навичка для Codex і Claude Code, яка досліджує інтерес до тем у мовних розділах Wikipedia та створює короткий PDF. Агент уточнює запит і перевіряє зміст статей; TypeScript CLI зіставляє концепції через Wikidata, отримує перегляди, обчислює показники й формує звіт. Навичка не викликає LLM API самостійно й не потребує власного сервера чи ключів LLM.

Можна дослідити окрему статтю або зафіксований тематичний набір, порівняти мови та періоди, перевірити стійкість динаміки й продовжити збережене дослідження. Джерела, пропуски та межі зіставлення залишаються видимими у результатах.

## Встановлення

Потрібні Node.js **24.21.0** з [.nvmrc](.nvmrc), npm, можливість запускати локальний Chromium і записувати файли в директорію навички. На етапі встановлення потрібен доступ до npm registry та завантажень Playwright. macOS перевірявся; Linux і Windows не підтверджені наскрізним запуском.

Скопіюйте вихідний код і відкрийте директорію, що містить цей README, SKILL.md та package.json. Якщо Git-репозиторій містить навичку в підкаталозі, спочатку перейдіть до `wiki-interest/`.

```bash
export WIKI_INTEREST_ROOT="$(pwd -P)"
nvm install
nvm use
npm ci --include=dev
npm run setup:browser
npm run --silent doctor -- --offline
npm run check
npm run --silent demo:offline
```

За відсутності nvm встановіть ту саму версію Node власним менеджером. DevDependencies потрібні для запуску TypeScript та перевірок. Збірка на диск не потрібна. `setup:browser` встановлює Chromium у `runtime/browser/`; для підтримуваного Playwright Linux-дистрибутива є `npm run setup:browser -- --with-deps` (може вимагати системних прав).

Після встановлення `check` і `demo:offline` працюють без Wikimedia, приватного контакту й платних модельних викликів. Демонстрація використовує **синтетичні fixtures**, створює новий run і PDF та повертає їхні ідентифікатори й шляхи. Це перевірка програми, а не дослідження реального попиту. Додаткові синтетичні сценарії: `npm run demo:topic` і `npm run demo:research`.

## Підключення до агента

Підключайте **всю директорію навички**, включно з кодом, залежностями й ресурсами. Підтримуються такі розташування:

| Область | Codex | Claude Code |
|---|---|---|
| Один робочий проєкт | `.agents/skills/wiki-interest/` | `.claude/skills/wiki-interest/` |
| Поточний користувач | `~/.agents/skills/wiki-interest/` | `~/.claude/skills/wiki-interest/` |

Це може бути окрема копія або локальний symlink до встановленої директорії. [Інструкція підключення](references/installation.md#codex-та-claude-code) містить команди без перезапису наявних файлів. Не переносьте чужі абсолютні symlink. Після підключення почніть нову сесію агента й перевірте, що він знаходить `wiki-interest`.

Приклад запиту:

> Порівняй інтерес до інтервального голодування в польській та чеській Wikipedia за останні два роки. Підготуй короткий PDF українською.

Для явного виклику додайте `$wiki-interest` у Codex або `/wiki-interest` у Claude Code. Модель сама читає SKILL.md і викликає CLI. Якість такого проходження недорогою моделлю ще не підтверджена: збережено [сценарії ручної оцінки](references/evaluation.md).

## Контакт Wikimedia

Публічний пакет **не містить особистого контакту чи готової live-конфігурації**. Перед першим live-дослідженням агент запитає ваш справжній email або URL зі способом зв’язку, якщо придатний контакт ще не налаштовано. Цей контакт передається Wikimedia у HTTP User-Agent; використовуйте лише той, який погоджуєтеся передавати.

Повний заголовок задається через `WIKIMEDIA_USER_AGENT`. Формат із навмисним placeholder показано лише в коментарі [.env.example](.env.example); його не можна надсилати Wikimedia. За потреби зберігайте справжнє значення у локальному `.env.local`, який ігнорує Git, і явно завантажуйте його в середовище процесу. Програма **не читає `.env` автоматично**. Не записуйте особистий контакт у публічний `package.json`, приклади чи звіти перевірок.

Після налаштування `npm run --silent doctor` перевіряє придатність конфігурації без HTTP і без друку контакту. Відсутність контакту блокує live, але не offline-тести, fixtures або створення PDF. [Докладне налаштування](references/installation.md#конфігурація-wikimedia) пояснює пріоритет конфігурації та передавання змінної агенту.

## Команди та результати

З будь-якої директорії запускайте CLI через фізичний корінь встановленої навички:

```bash
npm --prefix "$WIKI_INTEREST_ROOT" run --silent cli -- research --input examples/research.json
```

Це **live-приклад астрономії Q333**, який потребує контакту та HTTPS до Wikimedia. Для власної теми агент спочатку виконує `resolve`, читає статті й фіксує змістову відповідність через `review`. Для тематичного набору додаються `discover` і `plan`. [Контракти](references/contracts.md) описують усі операції; [SKILL.md](SKILL.md) — порядок роботи агента.

CLI повертає JSON зі `status`, `identifiers`, `summary`, `warnings`, `artifacts`, `nextAction`. Перевіряйте status: `partial` і `needs_selection` не є повним успіхом, хоча exit code дорівнює 0. Відносний `--input` завжди відраховується від кореня навички. Використовуйте лише `runId`/`reportId` зі свого виконання, а не чужі збережені ідентифікатори.

- Дослідження: `runtime/runs/<runId>/` — manifest, analysis, JSON/CSV рядів і додаткові файли тематичного аналізу.
- Звіти: `runtime/reports/<runId>/<reportId>/` — PDF, HTML, SVG, PNG сторінок і копії даних для відтворення. Точний шлях повертається в `artifacts`.
- Пошук, discovery, плани, snapshots і кеш також зберігаються у `runtime/` цієї копії.

Нове встановлення не потребує чужих звітів, кешу або symlink. `examples/demo-offline.json` працює з публічними fixtures. `examples/offline.json` демонструє інший режим: повторне використання **власного раніше завантаженого** кешу Wikimedia; це не початкове демо. Приклади revise/report/inspect потребують runId, створеного вами.

## Перевірки та обмеження

`npm run check` виконує TypeScript, Vitest, перевірку SKILL.md, відносних посилань, npm-команд і JSON-прикладів. PDF-тестам потрібен установлений Chromium. `npm run demo:offline` перевіряє повний синтетичний шлях до PDF. Успішні автоматичні перевірки не замінюють огляду PNG усіх сторінок і тесту поведінки агента.

Окремі `npm run smoke:live`, `npm run smoke:topic` та `npm run smoke:research` надсилають запити Wikimedia; запускайте їх свідомо після налаштування контакту. Вони не викликають LLM і не підміняють недоступні live-дані fixtures. [Поточний стан перевірок](references/implementation-status.md) відокремлює перевірене від невиконаного.

Перегляди Wikipedia не є унікальними людьми, розміром ринку чи готовністю платити; мова не є країною. Відсутність статті або дати не дорівнює нульовому інтересу. Wikidata QID не доводить однакового змісту статей. Обмежений пошук не доводить відсутності відповідника. Сплески не мають автоматично встановленої причини; два роки не доводять прогноз або сезонну модель. Тематична вибірка не гарантує репрезентативності.

## Публічний склад

Публікуються SKILL.md, TypeScript, конфігурація та lockfile, методологія, документація, шаблони в `src/reporting/`, тести, невеликі fixtures й приклади. `runtime/`, залежності, браузери, кеші, журнали та приватна конфігурація виключені [.gitignore](.gitignore). Правила діють лише всередині навички й не замінюють перевірку вже tracked/staged файлів.

LICENSE поки відсутній; рішення про ліцензування залишається за автором. Поле `private: true` у package.json запобігає випадковій публікації в npm і не заважає встановленню вихідного коду через `npm ci`.
